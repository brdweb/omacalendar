# OmaCalendar 2.0.2

A security hardening update for calendar parsing and the desktop runtime
directory. No IPC, schema, packaging, or feature change.

## Candidate identity

App 2.0.2; IPC 2.2; schema 3; current x86-64 Arch/Omarchy. The companion
widget pin is unchanged: widget 0.2.0 (signed tag `v0.2.0` at `ba25189`).
Runtime source: `ee84ec7` (PR #78) plus the 2.0.2 metadata and this record.

## Changed behavior

- The CalDAV/iCalendar codec scans each resource before handing it to libical
  and rejects it when components nest deeper than 32 levels, exceed 10,000
  components, or have unbalanced `BEGIN`/`END` lines. Event collection walks
  the component tree iteratively instead of recursively.
- `paths::ensureRuntimeDirectory` creates the fallback runtime directory (used
  when `XDG_RUNTIME_DIR` is unset) with mode `0700` without following an
  existing path, and refuses a runtime directory that is a symlink, not a
  directory, owned by another user, or (for the fallback) group- or
  world-accessible. The desktop single-instance lock and activation socket
  call it first, and the activation socket is created user-only.

## Interface and data

No IPC, schema, packaging, or configuration change. `docs/IPC.md` is
unchanged. A resource that exceeds the new structural limits fails to parse
as a malformed resource did before.
