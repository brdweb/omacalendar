## Known limitations

- Pending owner checks include all five views, dense-calendar drag/resize,
  accessibility, real widget bar edges, mixed-scale monitors, and native
  systemd activation on a clean Omarchy desktop.
- Live Google, complete Radicale, Nextcloud, Fastmail, and authenticated ICS
  acceptance remain distinct from deterministic provider tests.
- Flatpak has separate data and keyring identities. The native widget uses
  the native app/daemon; it does not connect to the Flatpak profile.
- Candidate packages must not be the only copy of important calendar data.
- The GitHub Flatpak bundle is not a Flathub listing or an automatic-update
  repository. AUR publication and widget marketplace approval are independent.

## Historical preparation evidence

The following results were collected during RC1 preparation, before the RC2
version-only replacement. Commit hashes and workflow links retain their
original identities. These results inform RC2 qualification but do not claim
that RC2 signed or downloaded artifacts have passed any pending gate.

Local preparation evidence on 2026-09-08: the current-Arch functional matrix
(21 configured tests including performance correctness), QML lint, daemon
startup/restart, and synthetic beta-to-RC upgrade/older-backup restore passed.
The separate 100,000-event reference-hardware run passed with p95 agenda
43.147 ms, search 5.101 ms, full widget snapshot 85.928 ms and unchanged snapshot
1.542 ms. An earlier timing run while both package compilers were active
exceeded the widget gate at 124.682 ms; it is not counted as a passing run.
These are preparation results; final signed/downloaded artifact verification
must be recorded in the attached candidate verification receipt.

The clean hosted GCC Debug, Clang RelWithDebInfo, ASan/UBSan, Arch baseline,
source metadata, dependency review and secret-scan jobs passed for preparation
commit `1721b47` ([CI run](https://github.com/brdweb/omacalendar/actions/runs/34299687474)).
Local Ubuntu 26.04 native compilation and all 21 configured tests passed;
two `.deb` assemblies were identical and clean apt installation, documentation,
private libical/secret-tool resolution, daemon restart, desktop scales and
removal passed. Local Flatpak installation, isolation, CRUD/undo, persisted
restarts, scenegraph startup, concurrent backend lifetime and removal passed.
Local package builds omit the protected Google client; only hosted release
builds are distribution candidates. Real Radicale and authenticated HTTPS ICS
smoke passed with synthetic credentials and process-local TLS trust, without
using the owner's keyring or provider accounts.

The hosted rehearsal at `dc272f5` passed Arch and Ubuntu package jobs. Its
downloaded native binaries passed startup with Google configured, real isolated
Radicale/authenticated HTTPS ICS, and beta upgrade/backup recovery. A 15-sample
widget timing run exceeded the gate (159.953 ms p95). A controlled paired
comparison with five warmups and 31 samples passed all timing gates for both
the published beta and candidate: widget p95 71.146 ms and 69.986 ms,
respectively. Both results are retained; timing is not inferred from hosted CI.
The rehearsal caught an older Flatpak builder choosing `/app/lib64`; dependency
installation and pkg-config lookup now explicitly use `/app/lib`. Final tag
builds and downloaded package checks remain required in the attached receipt.

Additional preparation checks passed: actual pacman installation/removal in a
fresh Arch container, including declared runtime dependencies and desktop
scales; repeated Flatpak GUI shutdown/reopen with a persistent backend; and
cross-sandbox activation of one desktop instance. Flatpak activation now uses
a persistent kernel lock so reused namespace PIDs cannot preserve a dead GUI's
ownership. A subprocess-kill regression covers recovery; native locking is
unchanged. The complete native 21-test matrix and QML lint passed after the fix.
Package SPDX finalization has ten regression tests and was validated against
the official SPDX 2.3 schema on all three real package stages. It records actual
file hashes, app versions and source-pinned bundled libraries, with external
host/KDE-runtime dependencies explicitly outside its inventory scope.
