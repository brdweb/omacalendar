# OmaCalendar 1.1.0

A notification-hardening and desktop polish release. It focuses on how imported
calendar history and invitation alerts behave: adding a calendar with old
reminders or past invitations no longer floods the notification center, and
invitation state survives daemon restarts.

App 1.1.0; IPC 2.0; schema 2 (additive in-place schema repairs only). The
companion widget is independently released.

## Notification behavior

- Reminders whose trigger time is more than two hours past and whose occurrence
  already started are dismissed silently. Reminders for still-upcoming
  occurrences deliver as catch-up when the daemon returns.
- Per-calendar "Mute alerts" silences both reminders and invitation
  notifications for that calendar.
- Invitation notifications cover recent invitations only; invitation history
  older than 48 hours past its occurrence end is imported silently. This also
  covers the yearly history backfill after adding a new calendar.
- Invitation baselines are durable: changes that arrive while the daemon is
  offline notify after restart instead of being swallowed.
- More than five simultaneous invitations collapse into a single digest
  notification.

## Desktop UI

- Inline connecting/queued/connected feedback on the Google, CalDAV and ICS
  account forms and a "Mute alerts" option for new local calendars.
- A cached-data sync indicator, actionable empty states, keyboard support for
  date cells, calendar reordering and the month overflow popup, theme tokens
  for spacing and radii, unified date/time formatting, responsive window
  minimums, and consistent glyphs with subtle transitions.

## Interface and data

- `invitations.list` adds additive `upcomingTotal`/`pastTotal` fields; see
  [IPC](../IPC.md). No schema version change: the release ships only the
  established in-place schema repair path.

## Known limitations

- Moving existing events between calendars is rejected with an explicit
  "unsupported" error; this was always the behavior and is now documented.
- All other limitations from [1.0.0](1.0.0.md) continue to apply.
