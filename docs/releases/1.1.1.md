# OmaCalendar 1.1.1

A correctness patch for all-day events whose upstream copy uses an inclusive
end date. No interface, schema, or feature change.

## Candidate identity

App 1.1.1; IPC 2.1; schema 2 (additive in-place schema repairs only); current
x86-64 Arch/Omarchy. The companion widget is independently released. The signed
tag, final package hash, and attestation verification will be recorded in the
GitHub release after the tag workflow completes.

## Fixed behavior

- Some publishers, including subscribed Google calendars, describe a one-day
  all-day event with an inclusive end date (`end.date`/`DTEND` equal to the
  start date). Both provider read paths now normalize such a span to the
  exclusive next-day end that the rest of the app assumes.
- An iCalendar payload containing an all-day event that ends before it starts
  is repaired to a one-day event instead of failing to parse as a whole, so one
  malformed `VEVENT` can no longer discard an entire subscription.
- Events already cached with the inclusive shape are repaired when read from
  the local database, so existing installations do not need a full resync.

## Interface and data

No IPC, schema, packaging, or configuration change. `docs/IPC.md` is unchanged.

## Known limitations

- An all-day span is repaired on read rather than reported: an upstream event
  whose end date precedes its start date becomes a one-day event, and the
  original malformed span is not surfaced to the user.
- All limitations from [1.1.0](1.1.0.md) continue to apply.
