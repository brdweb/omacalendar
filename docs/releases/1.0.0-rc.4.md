## Development qualification

PR #18's subsequent P2 startup review found that one failed legacy cache refresh
aborted restoration of later CalDAV accounts. The fix retains the aggregate
failure and reports an account-specific error while continuing through all
remaining accounts. Four regressions (enabled/disabled accounts with malformed
or unmatched retained data) reproduce missing healthy-account network activity
before the fix and pass afterward, including migration checkpoint preservation.
The exact final commit, hosted CI, and downloaded artifacts are recorded in the
post-build verification receipt.

Clean Omarchy 4.0.3 VM testing also reproduced a widget-activation race:
immediate installation after restoration could read the shell registry before
the asynchronous reload completed. The helper now waits up to five seconds for
the expected registry state, with unchanged rollback on command failure or
timeout. Delayed-registration and permanent-failure regressions cover both
readiness and rollback. Three consecutive real-shell install/restore cycles
passed with byte-identical restoration of the original shell and key bindings.
This development helper check must be repeated from the final RC4 package.

`15c06c654225f2c1e1e502a22b65316a749c65b6c6769d0237bd90c2c2a5d205`;
the app was `8d453e54be587a166ebac6bb2fb58710a66e07478ba15a7d390b8d3efbde1e7d`.
